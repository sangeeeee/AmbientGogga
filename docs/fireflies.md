# 萤火虫配置与节气兼容

萤火虫是客户端环境粒子。安装后会生成游戏目录下的 `config/ambientgogga-fireflies-client.toml`；仓库的 `config/` 中也提供带英文注释的默认配置。开发客户端使用 `run/config/` 中的同名文件。它与七影蝶的配置相互独立。

保存配置后，新生成粒子使用新的外观和运动参数，已有粒子会按出生时的参数自然消失。也可以退出客户端后修改再启动。

## 默认效果

| 参数 | 之前 | 现在 |
| --- | --- | --- |
| 随机峰值透明度 | 0.82–1.00 | 0.70–0.88，均值降低约 13% |
| 最大粒子半尺寸 | 0.060 方块 | 0.054 方块，降低 10% |
| 闪烁频率 | 约 0.143–0.223 次/秒 | 0.17–0.27 次/秒，略快约 20% |
| 光照 | 固定全亮 | 最低方块光照 14，保留环境光 |

透明度与最低光照一起控制视觉亮度；实际屏幕亮度还会受材质包、光影影响，13% 指的是峰值透明度均值的变化。粒子自身可在黑暗中可见，但不会给周围方块提供动态光源。

## 常用参数

配置文件已逐项标明用途和范围；所有刻数按正常速度 20 刻/秒计。

| 配置段 | 调节内容 |
| --- | --- |
| `fireflies` | 开关、高峰每秒生成尝试数、每粒选址次数、距玩家的水平/垂直范围、离地高度 |
| `fireflies.timing` | 开始时刻、生成频率上升/高峰/下降持续时间 |
| `fireflies.appearance` | 尺寸、峰值透明度、最低光照、闪烁频率、低谷亮度比例 |
| `fireflies.lifetime` | 粒子寿命、出生渐亮和消失渐暗时间 |
| `fireflies.motion` | 速度、飞行起伏频率、转向平滑程度、换向间隔、游荡范围 |
| `fireflies.seasons` | 萤火虫时节与真实模式的节气名单 |

默认生成窗口从 13000 刻开始：5000 刻渐增，5000 刻高峰，1000 刻渐减。高峰每秒最多尝试生成 10 粒；选址失败或游戏粒子设置会减少实际可见数量。窗口可以跨过一天的结束，三个阶段总时长超过 24000 刻时，按顺序截断至一天。

范围上下限写反时会自动交换；垂直范围设为 0 时在玩家当前高度选址。自然生成仍需满足原有的晴天、非积雪森林/平原、露天且附近有地面等条件。“全年”只取消季节限制，不取消这些条件。直接用粒子指令生成的粒子不经过自然生成条件。

## 萤火虫时节

```toml
[fireflies.seasons]
fireflySeason = "ALL_YEAR"
realisticSolarTerms = ["greater_heat"]
```

| 选项 | 行为 |
| --- | --- |
| `ALL_YEAR`（全年，默认） | 所有节气均可自然生成 |
| `SUMMER_ONLY`（仅夏季） | 立夏、小满、芒种、夏至、小暑、大暑 |
| `REALISTIC`（真实） | 按 `realisticSolarTerms` 名单，默认仅大暑 |

季节限制只在同时安装 **Ecliptic Seasons（节气）** 时生效，读取的是**游戏世界当前节气**，不是电脑的现实日期。没有安装时，三种选项均按全年处理。限制模式下，未同步日历或没有有效节气的维度暂不生成。跨出允许节气后停止新增，已有粒子自然淡出。

### 为什么真实模式默认选大暑

个体成虫寿命不能直接等同于整个地区的萤火虫活动季节。国家林草局转载的西双版纳植物园资料提到成虫约 7–20 天寿命，同时介绍了不同种类和当地活动情况；不能据此推出全国统一的发光日期。[国家林草局资料](https://www.forestry.gov.cn/lyj/1/lcstly/20260602/673335.html)

北京园林绿化局介绍大暑时引用“腐草为萤”的传统物候，并描述夜间萤火虫活动，因此这里选用**大暑这一约 15 天的传统盛夏物候窗口**作为游戏预设。这是区域性的近似，传统说法并非萤火虫生物起源的解释，也不是所有物种共同的发光日历。[北京园林绿化局节气资料](https://yllhj.beijing.gov.cn/ztxx/lhysh/sh/202308/t20230814_3221914.shtml)

例如，美国大烟山国家公园的同步萤火虫高峰可能在五月下旬到六月中旬之间，求偶活动持续约两至三周，说明地区、物种和当年环境都会改变窗口。[美国国家公园管理局资料](https://www.nps.gov/grsm/learn/nature/fireflies.htm)

因此名单可以自行调整，例如 `['lesser_heat', 'greater_heat']` 表示小暑至大暑。游戏中每个节气持续多少天由节气模组决定，这里不把现实成虫寿命转换为游戏粒子寿命。

可填写以下名称（大小写均可）：

| 季节 | 节气名称，按时间排列 |
| --- | --- |
| 春 | 立春 `beginning_of_spring`、雨水 `rain_water`、惊蛰 `insects_awakening`、春分 `spring_equinox`、清明 `fresh_green`、谷雨 `grain_rain` |
| 夏 | 立夏 `beginning_of_summer`、小满 `lesser_fullness`、芒种 `grain_in_ear`、夏至 `summer_solstice`、小暑 `lesser_heat`、大暑 `greater_heat` |
| 秋 | 立秋 `beginning_of_autumn`、处暑 `end_of_heat`、白露 `white_dew`、秋分 `autumnal_equinox`、寒露 `cold_dew`、霜降 `first_frost` |
| 冬 | 立冬 `beginning_of_winter`、小雪 `light_snow`、大雪 `heavy_snow`、冬至 `winter_solstice`、小寒 `lesser_cold`、大寒 `greater_cold` |

## 依赖与验证

节气仅作为 `compileOnly` 依赖，编译基准为 0.13.8.4.1，不打包进成品，也不自动添加到开发运行环境。需要联动时，请自行在游戏中同时启用对应 Minecraft 1.21.1 / NeoForge 的节气模组。可选依赖声明不限制节气版本号；不涉及 Forge 或其他 Minecraft 版本。

兼容层仅调用长期存在的公开 `EclipticSeasonsApi.getInstance().getSolarTerm(Level)`，并按节气名称判断，不依赖枚举下标或新版本专用接口。[官方 API 文档](https://ecliptic-seasons.readthedocs.io/en/latest/en/developer_api/)

离线核对了 0.4.2.4-alpha、0.10.5、0.12.18.7、0.13.8.4.1、0.15.0-rc-3 的接口，签名及节气名称一致。自动检查覆盖 24 节气过滤、跨日/零时长窗口、闪烁与淡入淡出、实际配置的 TOML 往返和非法值修复，以及没有节气依赖时兼容类能加载。构建不启动客户端；这些检查不等同于逐个版本的游戏内联动实测。
